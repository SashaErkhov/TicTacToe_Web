# Описание

## Наименование
TicTacToe_Web - Онлайн крестики-нолики 1 на 1 с личными аккаунтами, матчмейкингом и историей партий.

## Предметная область
База данных TicTacToe_Web предназначена для хранения информации о пользователях (их аккаунтах), историях матчей всех пользователей, историях всех ходов всех матчей, множестве текущих матчей. Система должна поддерживать: создание новых пользователей; их авторизация и аутентификация; создание и отслеживание матчей, и истории ходов внутри матча; выдачу истории матчей для конкретного пользователя, с фильтрацией; Заморозка матчей и их последующая разморозка для доигровки. Матчи бывают двух разных типов: с фиксированным размером и бесконечным(расширяющимся по мере заполнения поля)

# Данные
Краткую информацию о структуре бд можно подчерпнуть из ER.pdf 
Более подробную непосредственно из дампа - dump.sql.
Здесь упомяну ряд вещей: я намеренно не указал все возможные 
ограничения целостности. Оставил только те, что можно 
организовать с помощью CONSTRAINT. Тригеры намерено используется 
ограничено, из-за отношения Дейта к ним и из-за нежелания 
нагружать операции INSERT - они будут происходить довольно часто.
Обязанность сохранения целостности перекладывается на прикладную программу - backend.
Также не буду сильно распинаться в объяснении самих таблиц,
лишь приведу ряд внешних предикатов для настоящей базы данных:
 - Существует игрок, характеризуемый логином LOGIN, паролем PASSWD и уровнем мастерства LEVEL
 - Уровень мастерства игрока является неотрицательным числом.
 - Логин игрока является уникальным во всём множестве игроков.
 - Существует игра, характеризуемая идентификатором ID, первым игроком F_GAMER (возможно отсутствующим), вторым игроком S_GAMER (возможно отсутствующим), символом первого игрока F_OX, размерностью игры DIMENSIONS, которая может принимать значения большие 0, модификацией игры MODE (Фиксированное поле или бесконечное) и результатом RESULT.
 - Первый и второй игроки, если оба заданы, представляют собой разных игроков.
 - Первый и второй игроки используют разные символы (X и O).
 - Никакая игра не может одновременно иметь NULL в качестве первого игрока и NULL в качестве второго игрока.
 - Существует ход, характеризуемый идентификатором ID, владельцем OWNER, позицией POS(x,y), игрой GAME и временем выполнения DATE
 - В рамках одной и той же игры никакие два хода не занимают одну и ту же клетку

# Пользовательские роли
АБД "postgres" - все права  
Пользователь "gamer" - только права на вставку и выборку. Под этим пользователем будет работать прикладная программа. Пример скрипта по его определению:
```sql
CREATE USER gamer WITH PASSWORD 'pswd';

GRANT CONNECT ON DATABASE prod TO gamer;

GRANT USAGE ON SCHEMA public TO gamer;

GRANT SELECT, INSERT ON ALL TABLES IN SCHEMA public TO gamer;

ALTER DEFAULT PRIVILEGES IN SCHEMA public
GRANT SELECT, INSERT ON TABLES TO gamer;
```

# UI / API 
## UI:
Во время сдачи проекта будет доступен реальный сайт, где можно будет протестировать функционал. До тех пор будет достаточно довольствоваться информацией о страницах:
1) Логин/регистрация.
2) Лобби с кнопкой играть.
3) Игра. Доска 3 на 3, индикаторы хода. Возможно еще таймер и кнопка выйти или сдаться.
4) Профиль юзера.
5) Статистика.
